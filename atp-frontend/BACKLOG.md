## 一、部署前必须处理（M5 阻塞项）

### 1. ⭐ 生产没有 vite 代理

dev 下 `/api` 由 vite 转发到后端，并且**代理会摘掉 `Origin` 头** —— 那是为了绕开
「同源 POST 也带 Origin、`changeOrigin` 只改了 Host」导致的 403。

**这一招在生产不存在。** 部署时必须二选一：

| 方案 | 做法 | 代价 |
|---|---|---|
| **同源（推荐）** | nginx 同时服务 `dist/` 与反代 `/api` 到后端 | 浏览器带的 `Origin` 与 `Host` 一致，Spring 判定同源，不进 CORS 分支，什么都不用配 |
| 分域 | 前端设 `VITE_API_BASE=https://api.…` 直连 | 后端必须把前端域名加进 CORS 白名单，且要允许 `Authorization` 头与凭据 |

**没有第三条路** —— 前端无法在生产环境里摘掉浏览器自己加的 `Origin`。

### 2. SPA history fallback

路由用的是 history 模式（`/dashboard/cases`、`/login`）。直接访问或刷新这些
URL 时，服务器必须 rewrite 到 `index.html`，否则 404。

```nginx
location / {
  try_files $uri $uri/ /index.html;
}
```

### 3. 构建时注入的环境变量会进 bundle

Vite 在 **build 时**把 `VITE_*` 静态替换进 JS。所以 `VITE_DEMO_PASSWORD`
会明文出现在产物里，**任何能打开页面的人都看得到**。

这在本项目是可接受的（虚构演示账号、一次性口令、私有仓库的面试 demo），
但它不是「配置」而是「内容」—— 换到任何真实场景都必须去掉预填、改回手动输入。
构建命令里不设这个变量即可，登录页会留空。

### 4. 产物体积

`dist` 里 CSS ~690KB（gzip ~286KB），主要是 CJK 字体按 unicode-range 切出来的
上百条 `@font-face`。woff2 本身是按需加载的，首屏只会下到实际用到的子集。
真嫌大的话可以只保留 Noto Sans SC 的 400 一档，但正文与标题的字重差别会没了。

## 二、后端没接，前端也就没做

| 功能 | 现状 | 前提 |
|---|---|---|
| **「申请审批」** | 按钮在原位、置灰标 `M3` | 后端「案例变更 → 生成审批单」还没接（审批**决策**接口早就有） |

| **Agent 的「检索命中」面板** | 已移除 | SSE 里没有工具事件（AgentScope 把工具结果并进了 reasoning 流）。后端说通了之后事件形状是 `{"type":"tool",…}`，届时加回来 |

## 三、做得完但推迟了

按「演示时会不会被看见」排序。

### 会被看见的

- **案例详情的「重新校验」按钮** —— `GET /api/cases/{id}/validation` 接口是现成的，
  `api.caseValidation` 也写好了，只是没挂按钮。半小时的事，但演示脚本里不走这一步。
- **顶栏搜索 / `⌘K` / 通知** —— 目前是静态装饰。搜索要后端给接口；
  `⌘K` 命令面板可以纯前端做（在已加载的树里搜），但会和「树是一次全取」的前提绑死。
- **agent 对话刷新即丢** —— `conversationId` 存在内存里，刷新页面就换新会话，
  后端那边的上下文也就断了。存 `localStorage` 即可续上，但要处理「会话已被后端回收」的情况。
- **SSE 断线不重连** —— 一轮 1~3 分钟，中途断网就断了，没有重试。
  真要做得考虑「重连之后 thinking 从哪接」，不是简单重发。

### 不太会被看见的

- **窄屏 / 移动端** —— dashboard 按 1440 宽设计，`< 1280` 会挤。Landing 是响应式的。
- **深色模式** —— 和风精密那套配色是为纸白底做的，深色要重新配一遍，不是反色能了事。
- **树的搜索与过滤** —— 80 条案例还能翻，上千条就需要了。
- **ESLint** —— 没装。`tsc -b --noEmit` 覆盖了类型，但覆盖不了 hooks 依赖数组之类的。
- **测试** —— 一行没有。SSE 解析那段有价值（用真实流按随机边界重放），
  值得沉淀成 vitest 用例而不是留在 scratchpad 里。

## 四、还欠后端的两件事

1. **`case_code` 撞号仍报 500**（`DuplicateKeyException` / `uk_case_code`）。
   后端已给了 `…/problems/duplicate-case-code` 这个 type，前端**优先按 type 判**，
   匹配约束名只作兜底。等确认线上都走 type 之后，那段 fallback 可以删。
2. **取号不是原子的** —— 两个人同时新建同一模块的案例会拿到同一个号。
   前端已经做了「撞号自动重取一次」，但根治要后端在 commit 里分配号。

## 五、演示脚本里能跑通的路径（部署后先验这几条）

```
① 登录（口令已预填）→ 案例中心
② 选 ATP-ORDER-0001 → 规范校验标红 STD-001 → 点 finding 高亮到步骤表第 2 行
③ 派发执行（只 LOGIN / CART / ORDER）→ 进度条 2 秒一跳 → 拿到 204 自动停
④ 最近执行结果点带录像的行 → 抽屉里播 webm
⑤ ATP-LOGIN-0001（SLEEP）vs ATP-LOGIN-0002（显式等待）—— 十倍耗时差
⑥ ATP-ORDER-0003 点进失败详情 → BY DESIGN 说明卡
⑦ Agent 面板「写一条案例：…，模块 M003」→ 1~3 分钟 → 回案例中心看到新案例
⑧ 案例中心「新建」→ 选模块自动取号 → 填步骤 → 保存 → 提交落地
⑨ 审批中心批准一条 → 记录上是**当前登录者**（decidedBy 从 token 解）
```

agent 端到端跑通并带录像的四条演示资产：`ATP-CART-0013/0014`、`ATP-SEARCH-0011/0012`。
